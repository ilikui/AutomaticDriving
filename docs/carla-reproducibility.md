# CARLA 场景复现与回归测试

本指南把 CARLA 用作离线仿真与场景回归工具。它不是实车验证替代品；版本、地图、随机性、传感器配置与指标必须一起记录，否则“同一场景”不一定可复现。

## 1. 先固定实验环境

每次实验至少记录：

- CARLA server / Python API 版本、Scenario Runner 版本和 Git commit。
- 操作系统、GPU/驱动（若使用渲染）、运行模式（同步 / 异步）。
- 地图、天气、时间、交通参与者数量、车辆蓝图与传感器配置。
- 固定随机种子；记录交通管理器和场景生成器是否都使用该种子。
- 地图资产或自定义场景的来源与许可证。

官方入口：[CARLA 文档](https://carla.readthedocs.io/) · [CARLA GitHub](https://github.com/carla-simulator/carla) · [Scenario Runner](https://github.com/carla-simulator/scenario_runner)。

## 2. 建议的实验目录

```text
experiments/carla/
  README.md
  scenarios/
    baseline.yaml
  runs/
    <run-id>/
      manifest.json
      metrics.json
      events.jsonl
      notes.md
```

- `manifest.json`：提交 SHA、版本、地图、天气、种子、运行参数。
- `metrics.json`：指标、单位、统计窗口、计算方式。
- `events.jsonl`：碰撞、越线、超时、接管、传感器失效等事件。
- `notes.md`：失败原因、复现步骤、已知限制。

## 3. 场景配置模板

仓库提供 [`labs/carla/scenario-template.yaml`](../labs/carla/scenario-template.yaml)。它是实验记录模板，不会被 CARLA 自动读取；请根据所选 CARLA / Scenario Runner 版本，将字段映射到实际运行配置。

开始时一次只改变一个主要因素，例如天气、传感器噪声或目标车行为。保留一个固定基线场景，避免多项变化导致结果无法归因。

## 4. 最小指标集合

| 类别 | 指标 | 记录约定 |
|---|---|---|
| 任务结果 | 成功 / 失败 / 超时 | 明确终止条件，不能只记录平均值 |
| 安全代理指标 | 碰撞次数、最小 TTC、最小间距 | 定义对象范围、单位和采样频率 |
| 交通规则 | 越线、闯灯、逆行事件 | 记录事件时间与场景位置 |
| 轨迹跟踪 | 横向误差、航向误差、速度误差 | 同时报告均值、P95 和最大值 |
| 性能 | 仿真时长、实时因子、CPU/GPU、内存 | 区分仿真时间和墙钟时间 |
| 鲁棒性 | 不同种子重复结果、失败率 | 报告样本量和置信区间，不能只挑最好结果 |

TTC（Time To Collision）只适用于满足相应运动假设的情形；静止或交叉轨迹等场景应谨慎解释，不能单独用它证明安全。

## 5. 回归流程

1. 固定场景配置、版本、种子和初始状态。
2. 运行基线，保存原始日志与 manifest。
3. 修改单一因素，运行相同场景。
4. 比较任务结果、失败事件、分位数指标和资源占用。
5. 对异常结果做至少一次重复运行，区分算法回归与随机波动。
6. 把失败案例保留为回归用例，不要只保留成功截图。

## 安全声明

仿真结果只对已覆盖的模型、场景和假设提供证据。不得将单一仿真场景通过、低碰撞次数或较高成功率直接解释为真实道路安全证明。
