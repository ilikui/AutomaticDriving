# 自动驾驶工程实践手册

> 将自动驾驶知识从“知道概念”推进到“能读工程、能复现实验、能解释失败”。具体命令与接口以所选项目当前官方文档为准。

## 1. 系统边界与典型数据流

\`\`\`mermaid
flowchart LR
    S["Camera / LiDAR / Radar / IMU / GNSS"] --> T["时间同步与标定"]
    T --> P["环境感知与跟踪"]
    T --> L["定位与地图"]
    P --> F["融合世界模型"]
    L --> F
    F --> Pred["行为预测"]
    Pred --> Plan["行为决策与轨迹规划"]
    Plan --> Ctrl["横纵向控制"]
    Ctrl --> V["车辆接口与执行器"]
    V -. 状态反馈 .-> L
    Sim["仿真 / 回放 / 场景测试"] -. 验证与回归 .-> P
    Sim -. 验证与回归 .-> Plan
    Sim -. 验证与回归 .-> Ctrl
\`\`\`

该图是通用学习模型，不代表 Autoware、Apollo 或其他系统的精确内部实现。阅读具体代码时，应根据实际节点、Topic、接口和配置重新绘制数据流。

## 2. 模块接口检查表

| 模块 | 输入需要确认 | 输出需要确认 | 常见故障 |
|---|---|---|---|
| 传感器驱动 | 设备型号、采样频率、时间戳、单位 | 原始消息、状态码 | 丢帧、时间戳跳变、单位错误 |
| 标定与 TF | frame_id、外参方向、标定版本 | 坐标变换、标定参数 | 坐标系混淆、矩阵顺序错误 |
| 感知 | 图像/点云、内外参、模型版本 | 目标框、类别、置信度 | 坐标系不一致、域偏移、误检漏检 |
| 定位 | IMU、GNSS、轮速、地图 | 位姿、速度、协方差 | 漂移、初始化失败、地图匹配异常 |
| 融合与跟踪 | 多源目标、时间差、协方差 | 统一目标列表与轨迹 ID | 错误关联、重复目标、ID 抖动 |
| 预测 | 历史轨迹、道路拓扑 | 多模态未来轨迹及置信度 | 长尾行为、交互建模不足 |
| 规划 | 自车状态、障碍物、道路约束 | 可行轨迹、代价、失败原因 | 无解、抖动、约束冲突 |
| 控制 | 参考轨迹、车辆状态、执行器限制 | 转向/制动/驱动指令 | 延迟、饱和、模型失配 |
| 车辆接口 | 命令、车辆状态、通信诊断 | 执行器反馈、故障状态 | 超时、协议不匹配、失效安全不明确 |

## 3. 传感器融合的工程步骤

\`\`\`mermaid
flowchart TD
    A["读取多源观测"] --> B["检查时间戳与单位"]
    B --> C["变换到统一坐标系"]
    C --> D["时间对齐与运动补偿"]
    D --> E["数据关联 / 门控"]
    E --> F["融合状态与不确定度"]
    F --> G["输出质量标志与诊断信息"]
    G --> H["离线评估与回归测试"]
    H -. 失败样本回流 .-> A
\`\`\`

实施时逐项检查：

1. **时间**：记录采集、接收和处理时间；区分时钟同步误差与传输延迟。
2. **坐标系**：明确 frame、单位、轴方向、变换约定和外参版本。
3. **不确定度**：协方差应与状态定义、坐标变换和噪声假设一致。
4. **关联**：明确门控距离、关联策略、目标生命周期与 ID 管理规则。
5. **异常输入**：测试空消息、过期数据、离群值、传感器掉线和时间倒退。
6. **评估**：同时报告误差、延迟、可用率、失败样本和置信区间。

## 4. 车辆控制算法对比

| 方法 | 适合入门的问题 | 优点 | 需要注意 |
|---|---|---|---|
| PID | 单变量反馈与稳态误差 | 简单、易调试 | 多变量耦合、积分饱和与延迟 |
| Pure Pursuit | 几何路径跟踪 | 易实现、适合建立基线 | 前视距离影响响应和稳定性 |
| Stanley | 横向误差与航向误差 | 直观、实现简洁 | 速度变化、噪声与低速行为 |
| LQR | 线性化模型与二次型代价 | 可系统设计反馈增益 | 模型、权重和工作点依赖 |
| MPC | 约束下的有限时域优化 | 可显式处理约束 | 求解时间、模型误差与不可行问题 |

不要仅以单次轨迹的视觉效果判断控制器。至少记录横向误差、航向误差、控制量变化率、约束违反、计算延迟以及不同速度和曲率下的表现。

## 6. 调试与故障定位顺序

1. **复现**：固定版本、配置、输入数据、随机种子和运行命令。
2. **缩小范围**：用最小输入或 rosbag 回放，确认问题首次出现的模块。
3. **检查契约**：检查时间戳、frame_id、单位、数组长度、NaN/Inf 和 QoS。
4. **对照基线**：比较输入输出统计量、延迟、协方差和中间结果。
5. **构造反例**：增加边界、遮挡、延迟、离群值、掉线与极端运动测试。
6. **修复并回归**：增加能复现旧故障的测试，避免只做手工验证。
7. **记录限制**：说明哪些条件已验证，哪些尚未覆盖。

## 7. 从离线实验走向仿真

- **L0 合成数据**：验证公式、单位、边界条件和数值稳定性。
- **L1 公开数据集**：固定数据切分和评价协议，建立可比较基线。
- **L2 传感器回放**：检查时间戳、坐标系、消息频率和系统集成。
- **L3 封闭场景仿真**：固定路线、天气、交通参与者、随机种子和触发条件。
- **L4 场景集回归**：加入正常、边界、故障注入和长尾案例。
- **L5 受控实车验证**：仅在组织流程、风险评估、法规与安全保障满足要求后开展。

教学实验不能替代功能安全流程、道路法规要求、专业安全评审或实车验证许可。
